# Project audit

Audit date: 2026-10-21. Scope: files in this nested rebuild project only. The original installed program, installer, and user database were not accessed.

## Starting state

- `main.py` starts a PyQt6 application and delegates setup/login to the UI.
- `smartschool/database.py` creates an SQLite database under `%LOCALAPPDATA%`, has basic tables and parameterized value queries, and uses a module allowlist for dynamic table/column names.
- `smartschool/security.py` uses salted PBKDF2-HMAC-SHA256 (310,000 rounds) and constant-time digest comparison.
- `smartschool/ui.py` contains setup/login, dashboard, and basic student/teacher/class/subject CRUD and CSV export.
- There were no tests, migrations, logging setup, or other source files in the initial tree.
- Python 3.15 is available. A project-local `.venv` now contains the dependencies declared by `requirements.txt` and `requirements-dev.txt` (PyQt6 6.11.0 and pytest 8.4.2).

## Findings

### Strengths

- New rebuild uses a separate app-data directory and does not overwrite the legacy installation.
- SQL data values are parameterized; SQL identifiers are selected from a fixed internal mapping.
- Passwords are not stored in plaintext. Setup requires a 10-character minimum and has no default password.
- Foreign keys are enabled on connections, and the database uses a busy timeout.
- UI asks for confirmation before its permanent record deletion action.

### Material gaps

- The initial unversioned schema had no verified pre-migration backup mechanism. Version 1 now takes and integrity-checks a copy before changing an existing unversioned database.
- SQLite connections were not explicitly closed; this rebuild now centralizes commit, rollback, and close behavior.
- Failed login attempts were unlimited and not recorded.
- Roles were stored but not enforced for data changes; this rebuild enforces active-admin authorization in write services.
- Audit events were separate from the corresponding data transaction, so a change and its audit record could diverge.
- CRUD permits permanent deletion, and the audit log stores a username string rather than a user foreign key. Retention, actor identity, and tamper resistance need further design.
- Search uses `LIKE` without escaping `%` and `_`, has a fixed 1,000-row cap, and offers no pagination or sorting controls.
- CSV export does not mitigate spreadsheet formula injection and exports all records without an explicit export audit event.
- Legacy students store a free-text class name. Explicit session/class enrollment history is now available for new records, but no history is inferred for existing students. Subject/class assignments, assessments, billing, attendance, and reports are absent.
- UI catches broad exceptions and shows raw exception text. There is no centralized user-facing error handling or accessibility review.
- There is no backup/restore workflow, import validation, school profile, password change, session timeout, or administrator recovery process.
